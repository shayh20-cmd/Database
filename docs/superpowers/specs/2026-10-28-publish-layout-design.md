# מבנה הפרסום לכל פרויקט — SENT ו-UPDATED לפי רמות — מסמך עיצוב

**תאריך:** 2026-10-28
**קבצי יעד:** `tools/local-server/filing-plan.js` (בניית הנתיבים, זיהוי המבנה מהעץ), `tools/local-server/filing-ai.js`
(המפה: השדה `publish`), `tools/local-server/filing.js` (המפה, רשימת הסוגים של המשרד, `inbox-plan`),
`project_hub_01.html` (`SettingsFoldersView`, `InboxBatch`), `i18n-dict.js`, בדיקות ב-`tools/local-server/test/`.
**בסיס:** `2026-10-26-filing-without-ai-design.md` (תיוק בלי Claude, ה-slots `sent`/`sentSplit`/`updated`).
**סטטוס:** העיצוב אושר בשיחה עם המשתמש; ממתין לעיון במסמך הכתוב.

## הבעיה

הפרסום מתיבת הייצוא בונה את נתיב ה-SENT לפי מבנה קבוע אחד: שנה ← יום ← סוג
(`<code>-pub-sent-YYYY/<code>-pub-YYYY,MM,DD/PDF`). בפועל כל פרויקט בנוי קצת אחרת. בספרייה העירונית בלוד (LDLI)
הארכיון בנוי סוג ← שנה ← יום, ולתיקיית היום יש תיאור:

```
LDLI-pub-@sent/LDLI-pub-sent-PDF/LDLI-pub-PDF-2026/LDLI-pub-PDF-2026,10,19 - חניה זמנית
LDLI-pub-@sent/LDLI-pub-sent-DWG/LDLI-pub-DWG-2026/LDLI-pub-DWG-2026,10,25 - גרמושקה ליועץ בטיחות
```

הפרסום הראשון (28.10) נשלח ל-`LDLI-pub-@sent/LDLI-pub-sent-2026/LDLI-pub-2026,10,28/PDF` — בתוך PUBLISH, לא במקום.
גם UPDATED שם מחולק לפי סוג (`LDLI-pub-updated-PDF`, `-DWG`, `-DWF`), והקוד מכיר רק PDF לתיקייה אחת.
ואחרי התיוק לא הופיע בחלון כפתור לפתיחת התיקייה.

**המטרה:** כל פרויקט מגדיר ב-Project Hub את מבנה ה-SENT וה-UPDATED שלו, במדויק. המבנה מוצע אוטומטית מהתיקיות
הקיימות, המשתמש מאשר או מתקן, וחלון התיוק בונה ממנו את הנתיב של כל קובץ — עם אפשרות לשנות קובץ בודד.

## החלטות (מהשיחה)

| נושא | החלטה |
|---|---|
| איך מגדירים מבנה | **שרשרת רמות עם תבנית שם** (גישה 1). לכל רמה סוג (סוג קובץ / שנה / יום) ותבנית; הסדר חופשי. |
| הצעה ראשונית | "מלא אוטומטית" מזהה את הרמות והתבניות משמות התיקיות הקיימות. מיפוי האזורים עם Claude נשאר כמו שהוא. |
| תיאור לתיקיית היום | **שדה רשות בחלון**, מתווסף לשם: `… - חניה זמנית`. ריק — התאריך בלבד. |
| סוג קובץ ← תיקיית סוג | **רשימה אחת למשרד** (PDF: pdf · DWG: dwg, zip · DWF: dwf · DOCS: כל השאר), **ניתנת לעריכה לכל פרויקט**, ושינוי לקובץ בודד בחלון. |
| UPDATED | **כל הסוגים**, כל קובץ לתיקיית הסוג שלו; קובץ באותו שם עובר ל-`@ver` (כמו היום). נשאר צ'ק בוקס בכל פרסום. (מחליף את "PDF בלבד" של 2026-10-26.) |
| שינוי לקובץ בודד | "שנה" ליד הנתיב של הקובץ בוחר כל תיקייה מהעץ, לקובץ הזה בלבד. |
| אחרי התיוק | 📂 לכל תיקייה שתויקו אליה קבצים (הרשימה קיימת בקוד ולא הוצגה — לבדוק למה ולתקן). |
| מחוץ לתחום | קבצים שהתקבלו (יועצים, RECIEVE, PERMIT) ותוסף ה-Outlook — בלי שינוי. |

## מודל הנתונים

### המפה של הפרויקט: השדה `publish`

```js
map.publish = {
  sent: {
    base: 'LDLI-work/LDLI-publish/LDLI-pub-@sent',        // תיקייה בעץ
    levels: [
      { kind: 'type', pattern: 'LDLI-pub-sent-{type}' },
      { kind: 'year', pattern: 'LDLI-pub-{type}-{yyyy}' },
      { kind: 'day',  pattern: 'LDLI-pub-{type}-{yyyy},{mm},{dd}' }
    ]
  },
  updated: {
    base: 'LDLI-work/LDLI-publish/LDLI-pub-updated',
    levels: [{ kind: 'type', pattern: 'LDLI-pub-updated-{type}' }]
  },
  types: null          // null: רשימת המשרד; אחרת רשימה משלו (אותו מבנה כמו של המשרד)
}
```

- **תבניות:** טקסט עם `{code}` (קוד הפרויקט), `{type}` (שם תיקיית הסוג מהרשימה), `{yyyy}`, `{mm}`, `{dd}`.
  כל רמה חייבת את הסימון שלה: `type` ← `{type}`, `year` ← `{yyyy}`, `day` ← `{yyyy}`, `{mm}` ו-`{dd}`.
  כל סוג רמה מופיע לכל היותר פעם אחת. אחרי ההצבה כל רמה היא שם תיקייה תקין (`folderName`). רמה לא תקינה
  נזרקת בשמירה, והשרת מחזיר `400 { error: 'layout' }` עם מספר הרמה.
- **בלי רמת `type`** — כל הסוגים באותה תיקייה (זה מחליף את `sentSplit: false`). **בלי רמות בכלל** — הקבצים
  נכנסים ל-`base` עצמו.
- **התיאור** אינו סימון בתבנית: הוא מתווסף תמיד לסוף שם רמת ה-`day` כ-` - <תיאור>` (אחרי `safeName`, עד 60 תווים).
  ב-SENT בלי רמת `day` השדה לא מוצג.
- `cleanPublish(raw, tree)` ב-`filing-ai.js` מנקה: `base` רק נתיב יחסי תקין, רמות לפי הכללים, `types` לפי הכללים
  למטה. `normalizeMap` מחזיר `publish` (או `null` כשאין).

### רשימת הסוגים

```js
types = [
  { name: 'PDF',  ext: ['pdf'] },
  { name: 'DWG',  ext: ['dwg', 'zip'] },
  { name: 'DWF',  ext: ['dwf'] },
  { name: 'DOCS', ext: [], rest: true }     // בדיוק אחד עם rest: כל סיומת שלא ברשימה
]
```

- **של המשרד:** נשמרת ב-`filing.json` תחת `office.types`. ברירת המחדל היא הרשימה למעלה. עורכים אותה
  כותבים (editor, manager, admin), דרך `PUT /api/filing-hub/office-types`. `GET` מחזיר את הרשימה.
- **של פרויקט:** `map.publish.types`. כשהוא `null`, הפרויקט משתמש ברשימת המשרד.
- **שמות:** תקינים כשם תיקייה, עד 20 תווים, בלי כפילויות. סיומות באותיות קטנות, בלי נקודה, וכל סיומת בסוג אחד בלבד.

## בניית הנתיבים — `filing-plan.js`

### `publishPlan({ layout, types, tree, code, files, sent, updated, date, desc, pick, typeOf, dests })`

מחליפה את `inboxPlan` בפרסום. הפרמטרים:
- `layout`: ה-`publish` של המפה, או מה שזוהה מהעץ (למטה).
- `pick`: בחירת תיקיית היום. `null` — תיקייה חדשה. אחרת התיאור של תיקייה קיימת מאותו תאריך.
- `typeOf`: `{ n: 'DWG' }` — שינוי סוג לקובץ בודד.
- `dests`: `{ n: path }` — תיקייה מהעץ לקובץ בודד. היא מחליפה את יעד ה-SENT שלו בלבד.

לכל קובץ:
1. **הסוג:** `typeOf[n]`, אם נבחר. אחרת לפי הסיומת ברשימה, ואחרת סוג ה-`rest`.
2. **SENT:**
   - **בלי שינוי לקובץ:** מ-`base`, כל רמה בתורה מוסיפה תיקייה: התבנית אחרי ההצבה, וברמת `day` גם התיאור.
     - **תיקייה שכבר קיימת:** לכל רמה, תיקייה קיימת שהשם שלה שווה לשם שנבנה (בלי הבדל אותיות) משמשת כמו שהיא.
     - **רמת `day`:** כש-`pick` נבחר, משתמשים בתיקייה שהשם שלה הוא השם שנבנה ואחריו ` - <pick>`. כשאין כזו
       תחת הסוג הזה, היא נוצרת באותו שם.
     - **mkdir:** כל תיקייה חסרה בדרך נוספת כצעד `mkdir`, לפי הסדר ובלי כפילויות.
   - **עם שינוי לקובץ (`dests[n]`):** חייב להיות בעץ. אחרת הקובץ מקבל `problem: 'dest'` ונשאר בלי יעד SENT.
3. **UPDATED** (כש-`updated` מסומן): מ-`updated.base` לפי הרמות שלו (בדרך כלל רמת `type` בלבד), עם
   `replace: true`. רמה של שנה או יום ב-UPDATED נבנית כמו ב-SENT, בלי תיאור. תיקייה חסרה נוצרת.
4. התוכנית עוברת `ai.sanitizeInboxPlan`. רשימת ה"מותר להחליף" היא כל תיקיות ה-UPDATED שנבנו בתוכנית הזו.

התשובה: `{ plan, days, layoutFrom, slotsMissing? }`:
- `days`: התיאורים של תיקיות יום קיימות מהתאריך שנבחר, מכל הסוגים, בלי כפילויות. לבחירה בחלון.
- `layoutFrom`: מקור המבנה — `'saved'` (שמור במפה), `'detected'` (זוהה מהעץ עכשיו), `'convention'` (ברירת המחדל).
- `slotsMissing`: כמו היום, כשאין `base` או שהוא לא בעץ (`unmapped` / `gone`).

### `detectLayout(tree, base, types)` — זיהוי המבנה מהעץ

יורדים מ-`base` עד 4 רמות. בכל רמה בוחנים את תיקיות הבת:
- **סוג קובץ:** שמות שמכילים שם מהרשימה כמילה שלמה, מופרדת ב-`-`, `_`, רווח או סוף השם. למשל `LDLI-pub-sent-PDF`.
  התבנית היא השם עם `{type}` במקום השם מהרשימה.
- **יום:** שמות עם `YYYY,MM,DD`. התבנית היא השם עד סוף התאריך, עם `{yyyy},{mm},{dd}`. מה שאחרי התאריך (` - חניה
  זמנית`, `-01 - A4`) הוא תיאור או מספור ואינו חלק מהתבנית. שם סוג בתוך השם הופך גם הוא ל-`{type}`.
- **שנה:** שמות עם שנה בת 4 ספרות (19xx או 20xx) שאינם יום. התבנית היא השם עם `{yyyy}`, ושם סוג הופך ל-`{type}`.
- **בחירת התבנית:** הנפוצה ביותר בין הבנות. נכנסים לבת אחת מהסוג שזוהה, האחרונה לפי שם, וממשיכים. עוצרים
  ברמת יום שאין מתחתיה תיקיות סוג, או כשאין זיהוי.

בעץ של LDLI זה נותן סוג ← שנה ← יום, עם התבניות שבדוגמה. במוסכמה (`LDPB-pub-sent-2026/LDPB-pub-2026,10,01/PDF`)
זה נותן שנה ← יום ← סוג (`{type}`). כשאין שום זיהוי (ארכיון ריק), המבנה הוא של המוסכמה:
`{code}-pub-sent-{yyyy}` ← `{code}-pub-{yyyy},{mm},{dd}` ← `{type}`.

ל-UPDATED: אותו זיהוי מתחת ל-`updated.base`.

### מעבר ממפות קיימות

- **מפה עם `publish`:** משתמשים בו (`layoutFrom: 'saved'`).
- **מפה בלי `publish`:**
  - `base` של SENT: `slots.sent`. כשהוא ריק — `autoSlots(tree)` (כמו התיקון של PR #49).
  - `base` של UPDATED: ההורה של `slots.updated`, כשהשם שלו נגמר בשם סוג מהרשימה (`…-updated-PDF`). אחרת
    `slots.updated` עצמו, בלי רמות.
  - הרמות: `detectLayout`, וכשאין זיהוי — המוסכמה.

  שום דבר לא נשמר עד שמישהו לוחץ "שמור מפה". `slots` נשאר במפה לתוסף ה-Outlook ולתאימות.

## השרת — `filing.js`

- **`PUT /api/filing-hub/map`:** מקבל גם `publish`. הוא עובר `cleanPublish`, ו-`400 { error: 'layout', level }`
  כשרמה לא תקינה. בלי `publish` בבקשה — נשאר מה שהיה, כמו `slots`.
- **`POST /api/filing-hub/map-auto`:** מחזיר גם `publish: { sent, updated }` שזוהה (`detectLayout`) לצד `slots` ו-`areas`.
- **`GET` / `PUT /api/filing-hub/office-types`:** רשימת הסוגים של המשרד. `PUT` לכותבים בלבד.
- **`POST /api/filing-hub/inbox-plan`** (פרסום): מקבל גם `desc`, `pick`, `typeOf`, `dests`. בונה עם `publishPlan`
  ומחזיר `days` ו-`layoutFrom`. קבלת קבצים (`mode: 'receive'`) בלי שינוי.
- **`GET /api/filing-hub/project`:** מחזיר גם `types` (של הפרויקט או של המשרד) ו-`officeTypes`.

## Project Hub — הגדרות הפרויקט ← תיקיות הפרויקט

מקטע חדש **"פרסום"**, מתחת לאזורים. הוא מחליף את שלוש השורות של SENT / חלוקה לפי סוג / UPDATED:

- **SENT:**
  - **התיקייה:** בחירה מהעץ, כמו בשורות של היום, עם 📂.
  - **הרמות:** רשימה. בכל שורה: בחירת סוג (סוג קובץ / שנה / יום), שדה תבנית, ↑ ↓ ו-✕. בסוף "+ רמה".
- **UPDATED:** אותו דבר, בדרך כלל עם רמה אחת של סוג קובץ.
- **שורת תצוגה מקדימה:** לכל אחד מהשניים, לקובץ PDF מהיום, עם התיאור "<תיאור>". למשל:
  `LDLI-pub-@sent/LDLI-pub-sent-PDF/LDLI-pub-PDF-2026/LDLI-pub-PDF-2026,10,28 - <תיאור>`.
- **סוגי קבצים:** הרשימה בשימוש, בשורה אחת (`PDF: pdf · DWG: dwg, zip · DWF: dwf · DOCS: כל השאר`) וממה היא באה:
  - **"התאם לפרויקט":** פותח עורך על עותק לפרויקט. בכל שורה שם וסיומות, ✕, ו-"+ סוג". שורת ה-`rest` לא נמחקת.
  - **"חזור לרשימת המשרד":** מחזיר את הפרויקט לרשימת המשרד.
  - **"ערוך את רשימת המשרד":** לכותבים, באותו עורך. נשמר ב-`office-types`.
- **"מלא אוטומטית"** (קיים): ממלא גם את ה-`base` והרמות שזוהו. כמו היום — רק מה שריק, וההודעה אומרת כמה מולא.
- **הודעות שגיאה:** רמה לא תקינה מסומנת באדום, עם הסבר ("לתבנית של רמת שנה חסר {yyyy}").

## חלון התיוק — `InboxBatch`, פרסום

- **שורת SENT:** הצ'ק בוקס, התאריך, ושדה **תיאור (רשות)** ליד התאריך, עם placeholder "תיאור לתיקיית היום".
  - כשיש תיאורים קיימים מאותו תאריך (`days`), השדה מציע אותם כ-datalist. בחירה בתיאור קיים שולחת
    `pick: '<תיאור>'`; טקסט חדש שולח `desc`.
  - ההודעה מתחת: "תיקייה קיימת מאותו יום: <תיאור>" / "תיקייה חדשה".
- **רשימת הקבצים:**
  - בכל קובץ: צ'יפ סוג (select מהרשימה) והנתיב המלא שלו (SENT, ו-UPDATED כשמסומן), עם 📂 לתיקייה שכבר קיימת.
  - **"שנה":** פותח בחירה מתוך עץ ה-PUBLISH (חיפוש בשמות), לקובץ הזה בלבד. "בטל שינוי" מחזיר את הנתיב שנבנה.
- **UPDATED:** הטקסט "(PDF בלבד…)" מתחלף ב-"UPDATED (מחליף קובץ באותו שם)".
- **`layoutFrom`:**
  - `'detected'` או `'convention'`: הערה קטנה — "המבנה זוהה מהתיקיות. לשמירה: הגדרות הפרויקט ← תיקיות הפרויקט ← פרסום".
  - `'saved'`: בלי הערה.
- **אחרי התיוק:** 📂 לכל תיקייה שתויקו אליה קבצים. הרשימה (`rels`) נבנית מ-`f.paths` בתוצאה, ובמקרה של
  LDLI היא יצאה ריקה. לבדוק מה העוזר והשרת מחזירים (`paths` ליד `dests`), לתקן, ולהוסיף בדיקה.

כל הטקסטים בעברית ובאנגלית (`i18n-dict.js`). נתונים — נתיבים, תיאורים, שמות תיקיות — עם `data-i18n-skip`.
