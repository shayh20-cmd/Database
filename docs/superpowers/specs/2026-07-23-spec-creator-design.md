# מחולל מפרטים טכניים (ג2) — מסמך עיצוב

**תאריך:** 2026-07-23
**סטטוס:** עיצוב מאושר (עם ליטוש UX/גרפיקה שיימשך איטרטיבית)
**קובץ יעד:** `spec_creator.html` + הרחבת שרת ה-Node הקיים

---

## 1. רקע ומטרה

בכל פרויקט תכנון, בשלב המכרז מפיקים **מפרט טכני (ג2)** — מסמך משפטי המפרט את כל סוגי עבודות
הבנייה, דרישות הביצוע והתקנים שעל הקבלן לעמוד בהם. המפרט בנוי מ**ראשי פרקים קבועים**
(מתוך "האוגדן הכחול" / המפרט הכללי), כשכל פרק מכיל **תתי-פרקים** ו**סעיפים**.

רוב התוכן חוזר בין פרויקטים, אך כל פרויקט דורש התאמות (גמרים, מוצרים, סוג מבנה). המשרד
מחזיק מאגר מפרטים ומרכיב מהם ידנית בכל פעם. **המטרה:** מאגר ידע חכם לשימוש חוזר, שממנו
בונים במהירות מפרט לפרויקט חדש לפי PRESET, עורכים, ומייצאים ל-DOCX/PDF.

### היררכיית התוכן (נגזרה מהמפרט לדוגמה)
```
פרק (Chapter)          ── קבוע, מתוך רשימת פרקי האוגדן הכחול (~44). לדוגמה: "פרק 12 – עבודות אלומיניום"
  └─ תת-פרק (SubChapter) ── לדוגמה: "קיר מסך", "חלונות ודלתות", "מעקות", "כללי ותכולות עבודה"
       └─ סעיף (Clause)  ── טקסט הדרישה. **עץ** — סעיף יכול להכיל תתי-סעיפים (children)
```

## 2. החלטות מפתח (ממצה)

| נושא | החלטה |
|------|--------|
| מקור התוכן | **זריעה** מהמפרטים הקיימים (מתחילים ממפרט "מרכז קהילתי נווה יהושע" = מבנה ציבור). יבוא נוספים בהמשך. |
| ספרייה מול פרויקט | **Snapshot**: יצירת פרויקט מעתיקה תוכן מהספרייה. עריכה בפרויקט לא משפיעה על הספרייה/פרויקטים אחרים. כפתור "שמור חזרה לספרייה" לקידום שיפורים. |
| מודל סעיפים | **היררכי** (עץ). מספור נגזר מהמיקום בעץ — לא נשמר קשיח. |
| פורמט ייצוא | מסמך **Word נקי ומובנה** (כותרות, מספור, RTL, גופן סביר) + הדפסת PDF מהדפדפן. לא התאמת תבנית/מעטפת בשלב זה. |
| ארכיטקטורה | **React בקובץ HTML יחיד** (Babel standalone, ללא build) + **שרת Node מקומי** (הקיים, מורחב). מסלול נפרד מ-project_hub. |

## 3. מודל הנתונים

### א. הספרייה הראשית — `data/spec_library.json`

```js
library = {
  _ts: number,
  chapters: [{
    num: number,          // 12 (מספר פרק האוגדן; 41.5 אפשרי)
    name: string,         // "עבודות אלומיניום"
    discipline: 'ARCH' | 'STRC' | 'ELEC' | 'HVAC' | 'PLMB' | 'SAFE' | 'OTHER',
    subChapters: [{
      id: string,
      title: string,      // "קיר מסך / קיר זכוכית"
      clauses: Clause[]   // עץ (ראה למטה)
    }]
  }],
  presets: [{
    id: string,
    name: string,         // "מבנה ציבור"
    buildingType: string,
    // בחירת ברירת מחדל: אילו פרקים ותתי-פרקים דלוקים
    selections: [{ chapterNum: number, subChapterIds: string[] }]
  }]
}

// Clause — עץ רקורסיבי
Clause = {
  id: string,
  text: string,
  kind: 'paragraph' | 'standard' | 'heading',   // standard = שורת ת"י; heading = כותרת פנימית
  children?: Clause[]                            // תתי-סעיפים
}
```

**מספור:** לא נשמר. נגזר בזמן תצוגה/ייצוא מהמיקום: תת-פרק `12.01` → סעיף `12.01.03` → תת-סעיף `12.01.03.02`.
בסיס המספור לתת-פרק = `<chapterNum עם ריפוד>.<index תת-הפרק>`.

### ב. פרויקטים — `data/spec_projects.json`

```js
projects = {
  _ts: number,
  items: [{
    id, name, date, revision, buildingType, presetId,
    meta: { client?, address?, architect?, ... },
    chapters: [{                 // עותק (snapshot) של מה שנבחר מהספרייה
      num, name, discipline,
      included: boolean,
      subChapters: [{ id, title, included: boolean, clauses: Clause[] }]
    }]
  }]
}
```

`included` מאפשר לכבות פרק/תת-פרק מבלי למחוק את תוכנו (ה-toggle במוקאפ). פריטים כבויים
לא מיוצאים.

## 4. ארכיטקטורה ורכיבים

### דפדפן — `spec_creator.html` (React 18, single-file)
- **ProjectWizard** — אשף פרויקט חדש: שם/תאריך/מהדורה/סוג מבנה → בחירת PRESET → יצירת snapshot.
- **ChapterTree** (סרגל ימני, RTL) — פרקים→תתי-פרקים, toggle כלול/לא-כלול, "הוסף תת-פרק", תיוג דיסציפלינה (אדריכלות מודגש, אחרים אפורים/כבויים).
- **ClauseEditor** — עריכת עץ הסעיפים של תת-הפרק הנבחר: `contenteditable` לכל סעיף, שינוי סדר (▲▼ + גרירה), מספור אוטומטי, הוספת סעיף/תת-סעיף/תקן, המרה לסעיף-אב, מחיקה.
- **PresetManager** — צפייה/עריכה/יצירה של PRESETים.
- **LibraryManager** — עיון/עריכה של הספרייה הראשית + יבוא DOCX.
- **ExportBar** — ייצוא DOCX (שרת) / הדפסת PDF (תצוגת הדפסה בדפדפן).

**כל רכיב בקובץ נפרד לוגית / גבול ברור:** ChapterTree לא יודע על ClauseEditor אלא דרך
`activeSubChapterId` + callbacks; ClauseEditor מקבל `clauses` + `onChange` בלבד.

### שרת Node — הרחבת `tools/local-server/server.js`
מוסיף למפת `APPS` הקיימת:
- `GET/POST /api/spec-library` → `data/spec_library.json`
- `GET/POST /api/spec-projects` → `data/spec_projects.json`

מסלולים חדשים (מעבר לתבנית ה-JSON הפשוטה):
- `POST /api/spec/import` — מקבל DOCX (base64/multipart), מפרק לפי סגנונות פסקאות
  (כותרת פרק→chapter, כותרת מודגשת→subChapter, פסקה→clause, זיהוי `ת"י`→kind:standard,
  זיהוי היררכיית רשימות→children) ומחזיר מבנה `chapters[]`. תלות: **`mammoth`**.
- `POST /api/spec/export` — מקבל JSON פרויקט, מחזיר `.docx` בנוי (RTL, סגנונות כותרות,
  מספור). תלות: **`docx`**.
- PDF: הדפסת תצוגה מעוצבת בדפדפן (`window.print()` + CSS print) — ללא ספריית PDF בשרת.

### launch.json — קונפיג חדש `spec-creator` (פורט ייעודי, למשל 3404).

## 5. שלב הזריעה (חד-פעמי, מבוצע ע"י Claude)

Parser ש ממפה את `...מפרט ג2 - 08.docx` ל-`spec_library.json`:
1. פירוק הפסקאות (mammoth / docx XML) והיוריסטיקה על הסגנונות (`סגנון טקסט`, `Body Text`,
   `List Paragraph`, כותרות פרקים).
2. זיהוי גבולות פרקים ("פרק NN – שם" / "סוף פרק NN").
3. זיהוי תתי-פרקים (כותרות מודגשות/`סגנון טקסט`) וסעיפים; בניית עץ children מרשימות.
4. תיוג `discipline` לפי מספר הפרק (טבלת מיפוי קבועה).
5. בניית PRESET "מבנה ציבור" מהפרקים/תתי-הפרקים שנמצאו.
6. **בדיקה ידנית** של Claude על הפלט — הסגנונות במקור אינם עקביים; זהו הסיכון/מאמץ הגבוה בפרויקט.

> אותו pipeline משמש גם ל-`/api/spec/import` בהמשך — קוד משותף.

## 6. היקף MVP (YAGNI)

**כלול:**
- זריעת ספרייה מהמפרט לדוגמה (PRESET "מבנה ציבור").
- אשף פרויקט + ChapterTree עם include/exclude + הוספת תת-פרק.
- ClauseEditor היררכי עם שינוי סדר ומספור אוטומטי.
- PresetManager (PRESET אחד לעריכה + יצירת נוספים).
- ייצוא DOCX + הדפסת PDF.
- יבוא DOCX להרחבת הספרייה.

**נדחה להמשך:**
- וריאנטים מרובים לכל תת-פרק (בחירה בין נוסחים).
- התאמת תבנית/מעטפת/לוגו מדויקת בייצוא.
- השוואת מהדורות (diff בין revisions).
- ריבוי משתמשים / הרשאות.
