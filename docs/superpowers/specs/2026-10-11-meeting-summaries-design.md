# סיכומי ישיבות — עורך חדש בפורמט A4 · מסמך עיצוב

**תאריך:** 2026-10-11
**קובץ יעד:** `project_hub_01.html`
**סטטוס:** מאושר לתכנון (שלב 1). שלב 2 (ייבוא סיכום חיצוני דרך הקונקטור) — מסמך נפרד.

## הבעיה

עורך הישיבות הנוכחי (`MeetingEditor`, `MeetingItemsTable`) הוא רשימה שטוחה של שורות שהמספר
שלהן ("1", "1.1") נכתב ידנית, עם שלושה כפתורי הוספה נפרדים ובלי שינוי סדר. המשתתפים נבחרים
אחד-אחד בכל ישיבה. ההדפסה היא טבלה נפרדת שנבנית מהמספרים (`buildPrintGroups`).

המטרה: סיכום שנכתב במחשב, נוח לעריכה, ממוספר אוטומטית, ונראה כמו הרפרנס של המשרד —
טבלה פשוטה `# | נושא | תיאור | אחראי | לטיפול` בעמוד A4. ההשראה למבנה: Site Note
(`site_note.html`) — נושאים כראשי סעיפים, משימות תחתיהם, נספח תמונות, וישיבת המשך שממשיכה
את הפתוחים.

## מבנה העמוד

העורך הוא עמוד A4 (רוחב 210 מ"מ, שוליים 15 מ"מ) — מה שרואים על המסך זה מה שמודפס.

1. **כותרת:** שם הפרויקט · נושא הישיבה · תאריך.
2. **משתתפים:** שורת "נכחו: שם (תפקיד), …". במסך — עריכה (ראו "משתתפים").
3. **טבלת הסעיפים:**

   | # | נושא | תיאור | אחראי | לטיפול |
   |---|------|-------|-------|--------|

   - תאי `#` ו`נושא` נמתחים (rowSpan) על כל הסעיפים של הנושא — כל נושא נראה כשורה אחת עם
     מסגרת, כמו ברפרנס. בין סעיפים של אותו נושא אין קו אופקי.
   - כל **סעיף** (1.1, 1.2) הוא שורה עם אחראי ותאריך יעד משלו.
   - **תתי סעיפים** (1.2.1, 1.2.2) הם שורות טקסט בתוך תא התיאור של הסעיף, מוזחות, בלי
     אחראי ותאריך.
   - סעיף שהגיע מישיבה קודמת: מתחת לתאריך, בקטן — "מישיבה DD/MM".
   - סעיף עם תמונות: סמל קטן + "נספח א'" ליד הטקסט.
   - סעיף מקושר לפרויקט (משימה / עקרון / אבן דרך / יעד): צ'יפ קטן ליד הטקסט, לא מודפס.
   - כותרת הטבלה אפורה בהירה, מסגרות שחורות דקות.
4. **רשם · תפוצה.**
5. **נספח תמונות** (עמוד חדש, רק אם יש תמונות): כל תמונה עם הכיתוב "סעיף 1.2 — תחילת הטקסט".

### מספור

המספרים לא נשמרים — הם מחושבים מהסדר: נושא n, סעיף n.k, תת סעיף n.k.j. שינוי סדר הנושאים
או הסעיפים ממספר מחדש הכול. נושא בלי סעיפים מוצג כשורה עם תיאור ריק.

### אחראי

שני חלקים, שניהם אופציונליים: **תחום/משרד** (מרשימת התחומים של הפרויקט, כמו היום, + "לידיעה")
ו**שם** (ממשתתפי הישיבה, או טקסט חופשי). מודפס כ"קונסטרוקציה – יוסי", או רק אחד מהם.
התחום הוא מה שעובר למשימה כשמקשרים סעיף לפרויקט.

### עריכה

- לחיצה על טקסט = עריכה במקום (textarea שגדל לפי התוכן).
- **Enter** בסוף סעיף — סעיף חדש מתחתיו באותו נושא. **Shift+Enter** — שורה חדשה באותו סעיף.
- **Tab** — הסעיף הופך לתת סעיף של הסעיף שמעליו. **Shift+Tab** — חוזר להיות סעיף.
- **Backspace** בסעיף ריק — מוחק אותו ומתמקד בקודם.
- נושא: ידית גרירה לשינוי הסדר; "+ נושא" בתחתית הטבלה; "+ סעיף" בתוך כל נושא.
- תפריט קטן לכל סעיף (מופיע במעבר עכבר): הוסף תמונה · קשר לפרויקט (הקיים: משימה /
  תת-משימה / עדכון / עקרון / אבן דרך / יעד) · הזז למעלה/למטה · מחק.
- כל עמודות הכלים (ידיות, תפריטים, צ'יפים) מוסתרות בהדפסה.

## נתונים

```js
meeting = {
  id, trackId, title, date, recordedBy, distribution, createdAt,
  participants: [{ id, name, role, firm? }],
  sections: [{ id, title }],                 // הסדר במערך = סדר הנושאים
  items: [{
    id, sectionId, parentId,                 // parentId ≠ null → תת סעיף
    topic,                                   // הטקסט (שם השדה נשמר לתאימות: חיפוש, רשימות, הקונקטור)
    assignee,                                // תחום (כמו היום) | 'לידיעה' | null
    person,                                  // שם האחראי | ''
    dueDate, startDate,
    carriedFrom,                             // { meetingId, date } | null
    photos: [{ id, url, name }],
    itemType, createdTaskTrackId, linkedRecordId, linkedRecordKind   // הקישור הקיים
  }],
  basedOnMeetingId                           // אם נוצרה מישיבה קודמת
}
project.participantLists = [{ id, name, members: [{ name, role, firm? }] }]
```

סדר הסעיפים בתוך נושא = הסדר שלהם במערך `items`.

## ישיבה חדשה

"+ ישיבה חדשה" פותח בחירה:

1. **ריקה.**
2. **על בסיס הישיבה הקודמת** (האחרונה לפי תאריך באותו מסלול; אם אין — לא מוצג): מעתיקה
   משתתפים, נושאים, כל הסעיפים ותתי הסעיפים, רשם ותפוצה. כל סעיף מועתק מקבל
   `carriedFrom` = הישיבה המקורית — אם כבר היה מועתק, נשאר התאריך הראשון. **לא מועתקים:**
   תמונות וקישורים לפרויקט (המשימה כבר קיימת). המשתמש מוחק מה שלא רלוונטי.
3. **מרשימת משתתפים:** ריקה, עם המשתתפים של הרשימה שנבחרה.

## משתתפים

- **טען רשימה** — מוסיף את חברי הרשימה (בלי כפילויות לפי שם).
- **+ משתתף** — מתוך יועצי הפרויקט ואנשי הקשר (המקור הקיים: צוות + אנשי קשר של יועצים),
  או הזנה ידנית (שם, תפקיד).
- שינויים בישיבה לא משנים את הרשימה השמורה.
- **שמור כרשימה** — שומר את המשתתפים הנוכחיים כרשימה חדשה (שם) או מעדכן רשימה קיימת.
- ניהול הרשימות (שינוי שם, מחיקה) — מתוך תפריט "טען רשימה".

## תמונות

- העלאה דרך `/api/upload` הקיים (כמו קבצים במשימות); נשמר `{id, url, name}`.
- גרירת תמונה לסעיף או בחירה מהתפריט. כמה תמונות לסעיף.
- נספח: האותיות לפי סדר הופעת הסעיפים (א', ב', …), שתי תמונות בשורה, כיתוב "סעיף n.k".

## המרת סיכומים קיימים

ישיבה שיש בה `items` בלי `sectionId` (כל הישיבות הקיימות, וגם פריטים שהקונקטור מוסיף עד
שלב 2) מומרת בזמן הפתיחה, בפונקציה טהורה `migrateMeeting(meeting)`:

- פריט במספר שלם (1, 2) → נושא (`title` = הטקסט).
  אם היו לו אחראי, תאריכים או קישור → הוא גם הסעיף הראשון בנושא (הטקסט + השדות), כדי שלא
  יאבד מידע.
- x.y → סעיף בנושא x. x.y.z → תת סעיף של x.y.
- פריט בלי מספר תקין, או שהנושא שלו לא קיים → סעיף בנושא אחרון / נושא "כללי".
- הסדר המקורי נשמר.

ההמרה נשמרת רק בלחיצה על "שמור" (כמו כל עריכה בעורך היום). פתיחה וסגירה לא משנות כלום.

## לוגיקה טהורה

בלוק `/* ═══ meeting-logic ═══ */ … /* ═══ /meeting-logic ═══ */`, נבדק ישירות מהקובץ (כמו
`admin-logic` ו`home-logic`):

- `migrateMeeting(meeting)` → ישיבה במבנה החדש (מחזירה את אותה ישיבה אם כבר במבנה החדש)
- `meetingRows(meeting)` → שורות לתצוגה: `[{section, number, items:[{item, number, subs:[{item, number}]}]}]`
- `indentItem(items, id)` / `outdentItem(items, id)` / `moveSection(sections, id, dir)` /
  `moveItem(items, id, dir)` → מערכים חדשים
- `followUpMeeting(prev, {id, date})` → ישיבה חדשה מהקודמת (כללי ההעתקה למעלה)
- `photoAppendix(meeting)` → `[{letter, number, item, photo}]`
- `assigneeText(item, disciplines)` → "קונסטרוקציה – יוסי"

## הדפסה

`@page { size: A4; margin: 15mm }`. העמוד במסך באותו רוחב, כך שמה שרואים = מה שמודפס.
שורות נושא לא נשברות בין עמודים כשאפשר (`break-inside: avoid` על קבוצת הנושא; נושא ארוך
מעמוד — נשבר בין סעיפים). כותרת הטבלה חוזרת בכל עמוד (`thead`). הנספח מתחיל בעמוד חדש.
הטבלה הנפרדת להדפסה (`meeting-print-table`, `buildPrintGroups`) יוצאת — אותה טבלה משמשת
למסך ולהדפסה.

## מחוץ לתחום (שלב 2)

ייבוא סיכום חיצוני (PDF / Excel) דרך הקונקטור: עדכון `create_meeting` / `add_meeting_items`
למבנה החדש (נושאים, סעיפים, תתי סעיפים, שם אחראי), ופעולה שמכניסה ל-HUB רק את הסעיפים
שהמשתמש בחר. עד אז, פריטים שהקונקטור כותב במבנה הישן מומרים בפתיחה.

## בדיקות

- יחידה: כל פונקציות `meeting-logic` — המרה (כולל ראש נושא עם אחראי, מספרים חסרים, תתי
  תתי סעיפים), מספור אחרי הזזה, הזחה/ביטול הזחה, ישיבת המשך (carriedFrom נשמר מהמקור, בלי
  תמונות וקישורים), נספח.
- דפדפן: ישיבה קיימת נפתחת מומרת ונשמרת; עריכה במקלדת (Enter, Tab, Shift+Tab, Backspace);
  גרירת נושא ממספרת מחדש; תמונה לסעיף מופיעה בנספח; ישיבה על בסיס קודמת; טעינה ושמירה של
  רשימת משתתפים; קישור סעיף למשימה; תצוגת הדפסה ב-A4 בלי כלי עריכה.
