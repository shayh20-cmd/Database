## הבעיה

הדף של PR #50 מסובך: לכל אזור שדה "איך בנויה", ולפרסום שרשרת רמות עם תבניות (`{type}`, `{yyyy}`) שקשה להבין.
רוב התיוק הוא שניים: מה ששולחים (PUBLISH) ומה שמקבלים מיועצים (CONSULTANTS). את השאר מספיק למפות לתיקייה ראשית.

## מודל הנתונים — `map.publish`, גרסה 2

```js
publish = {
  sent:    { base: 'LDLI-work/LDLI-publish/LDLI-pub-@sent', byType: true,
             typeDirs: { PDF: '…/LDLI-pub-sent-PDF', DWG: '…/LDLI-pub-sent-DWG' }, date: 'year-day' },
  updated: { base: '…/LDLI-pub-updated', byType: true, typeDirs: { PDF: '…/LDLI-pub-updated-PDF' } },
  types: null
}
```

- `date`: `'year-day'` | `'day'` | `'none'` (SENT בלבד; ברירת מחדל `'year-day'`).
- `typeDirs`: מפתח = שם סוג מהרשימה; ערך = נתיב יחסי (relPath). מותר שיהיה חסר לסוג.
- **תאימות:** מבנה שמור של PR #50 (עם `levels` ובלי `byType`) ממשיך לעבוד בשרת כמו היום. הדף טוען אותו כגרסה 2
  (`byType` = יש רמת type; `date` לפי רמות השנה/היום; `typeDirs` ריק) ושומר בגרסה 2 (בלי `levels`).

## בניית הנתיב (שרת, `publishPlan`)

לכל קובץ, לפי הסוג שלו (רשימה / שינוי בחלון) — כמו היום, ורק החישוב של התיקייה משתנה:
- **תיקיית הסוג:** בלי `byType` — ה-`base`. עם `byType` — `typeDirs[type]` אם הוא בעץ; אחרת שם נגזר: אם תיקיית
  סוג אחר נבחרה ושמה מכיל את שם הסוג ההוא כמילה (`LDLI-pub-sent-PDF`) — אותו שם עם הסוג הזה; אחרת `base/<type>`.
  חסרה — נוצרת.
- **תיקיית תאריך (SENT):** `'none'` — כלום. אחרת התבניות של השנה והיום **מזוהות מהעץ**: `detectLayout` מתחת לכל
  תיקיית סוג קיימת (או מתחת ל-`base` כשאין חלוקה), ושם סוג בתוך השם הופך ל-`{type}`; הראשונה שנותנת שנה/יום קובעת.
  לא נמצא — המוסכמה: שנה `{code}-pub-sent-{yyyy}`, יום `{code}-pub-{yyyy},{mm},{dd}`. `'day'` — רק היום.
  התיאור מהחלון מתווסף לשם היום כמו היום.
- **UPDATED:** תיקיית הסוג בלבד, `replace: true`.
- `days`, `slotsMissing`, `problem` — כמו היום.

**בלי מבנה שמור** (`layoutFor`): `base` מ-slots / autoSlots כמו היום; `byType` ו-`typeDirs` מזוהים מהעץ (תיקיות
מתחת ל-base שהשם שלהן מכיל שם סוג); `date` לפי מה ש-`detectLayout` מצא. `map-auto` מחזיר את זה כ-`auto.publish`.

**Claude ("הצע"):** שורת ה-`Layout:` מתארת את גרסה 2 (base, תיקייה לכל סוג, סוג התאריך).

## "סייר" — בורר התיקיות של Windows, בתוך הפרויקט

- **משימה חדשה לעוזר:** `pick-sub` — פותח בורר תיקיות במחשב, שמתחיל בתיקייה שהדף ביקש (`start`, יחסית לפרויקט; ברירת
  מחדל תיקיית הפרויקט). מחזיר `{ rel }` — הנתיב היחסי לתיקיית הפרויקט — או `{ cancelled }`, או `{ missing }` כשתיקיית
  הפרויקט לא במחשב. תיקייה מחוץ לתיקיית הפרויקט — `{ outside: true }` (הדף אומר "התיקייה לא בתוך תיקיית הפרויקט").
- **שרת:** `POST /api/filing-hub/pick-sub { projectId, start }` → `taskId` (כותבים בלבד); התוצאה דרך `task?id=`
  כמו `pick`. `rel` נבדק ב-`ai.relPath`.
- **עוזר ישן** (לא מכיר את המשימה) — מבטל אותה; הדף אומר "עדכן את עוזר התיוק (הורד והתקן שוב)".
- הדף מחכה ל-`handed` 15 שניות (כמו בשאר), ואז FM_HELPER_OFF.
