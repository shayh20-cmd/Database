## הבעיה

מייל מיועץ מגיע עם תכניות; היום שומרים אותן ידנית לתיקיית הפרויקט בכונן הרשת, או דרך חלון
Receive של Folder Manager. התוסף כבר קורא את הקבצים המצורפים, אבל לא החלונית (דפדפן) ולא השרת
ב-Azure יכולים לכתוב לכונן הרשת של המשרד — התיוק חייב לקרות במחשב של המשתמש.

תבנית 154 התיקיות של Folder Manager לא מחזיקה בפועל: כל פרויקט קצת שונה (סוג פרויקט, טעויות).
לכן לא מסתמכים על התבנית אלא על **התיקייה הראשית של הפרויקט** ועל עץ התיקיות האמיתי שבה, ועל
הנחיית תיוק שהמשתמש מלמד לכל פרויקט.

מחוץ להיקף: תיוק מתוך Project Hub עצמו (לא מהמייל), סנכרון עם `projects.json` של Folder Manager,
שינויים בריפו של Folder Manager, כתיבה לרשם.

## הזרימה

1. **תיקיית הפרויקט** (פעם אחת): "בחר תיקייה" ← משימת `pick` לעוזר ← בורר תיקיות של Windows במחשב (נפתח
   מעל Outlook, מתחיל ב-`@Omicron Projects`, עם הצעה לפי קוד/שם מ-Folder Manager) ← השם נשמר בפרויקט.
   אם התיקייה שנבחרה לא יושבת ישירות ב-`projectsRoot` של המחשב, העוזר מעדכן את `projectsRoot` לתיקיית האב.
2. **הצעה**: "הצע" ← החלונית פותחת בקשה ומעלה את הקבצים המסומנים (כמו היום) ← השרת מבקש מהעוזר את עץ
   התיקיות (משימת `tree`, עד 20 שניות; נשמר לבקשה) ← Claude מציע ← החלונית מציגה את ההודעה והצעדים.
3. **תיקון**: טקסט חופשי ← Claude מציע מחדש עם כל השיחה של הבקשה (ההצעות הקודמות והתיקונים).
   Claude יכול גם לשאול שאלה (בלי הצעה) כשאינו יודע.
4. **אישור**: "אשר ותייק" ← משימת `file` לעוזר: מוריד את הקבצים, מבצע את התכנית (אותם כללי בטיחות), מדווח.
5. **סיום**: השרת רושם בהיסטוריה, ביומן המשימה המקושרת, והחלונית מציגה מה תויק ואיפה + 📂 פתח. אם Claude
   הציע `guide_add` — כפתור "הוסף להנחיה".
6. **לימוד ידני**: "תלמד: תכניות של מנהל הפרויקט נכנסות ל-RECEIVE\PM" בתיבת הטקסט (גם בלי קבצים) ←
   Claude מנסח `guide_add` ← "הוסף".

## עוזר הרקע והשרת

- משימות לעוזר הן מסוגים `pick`, `tree`, `open`, `file`. העוזר מחזיק בקשה פתוחה
  (`GET /api/outlook/filing-next`, long-poll עד 25 שניות, המפתח האישי) ומקבל את המשימה הבאה של אותו אדם עם
  אסימון חד-פעמי. מהרגע הזה האסימון הוא ההרשאה היחידה: `GET /api/filing/<token>` (פרטי המשימה),
  `GET …/file/<n>` (קובץ), `POST …/result` (התוצאה: עץ / תיקייה שנבחרה / מה תויק / נפתח), `POST …/cancel`.
- `open` ו-`tree` חיים 2 דקות; `pick` — 2 דקות עד שהמחשב לוקח אותה, ואז 10 דקות לבחירה; בקשת תיוק 15 דקות.
- אם אין עוזר שלקח משימה תוך 15 שניות — החלונית אומרת "עוזר התיוק לא פועל במחשב הזה" + פקודת ההתקנה.
- אדם שמחובר בשני מחשבים: המשימה הולכת למחשב ששואל ראשון.

## מה נשמר איפה

- **שרת, `data/filing.json`**: `{ projects: { <hubProjectId>: { folder, guide, updatedBy, updatedAt,
  log: [ … עד 200 ] } }, contacts: { <registerProjectId>: { at, by, list: [{ name, role, firm, emails[] }] } } }`
  (אנשי הקשר לפי פרויקט הרשם; פרויקט Hub מוצא אותם דרך `registerProjectId` שבמסמך שלו).
  רשומת log: `{ at, by, from, subject, file, dest, mode }`.
- **שרת, תיקייה זמנית** `DATA_DIR/filing-tmp/<job>/` — נמחקת בסיום, בביטול או כשפג תוקף.
- **מחשב**: `%LOCALAPPDATA%\ProjectHub\file-helper.json` `{ hub, projectsRoot }`, המפתח ב-`file-helper.key` (DPAPI),
  לוג ב-`file-helper.log`.

## התכנית של Claude

קלט: ההנחיה, עץ התיקיות (נתיבים יחסיים), 30 התיוקים האחרונים, אנשי הקשר של הפרויקט, שולח, נושא ותחילת
גוף המייל (עד 1,500 תווים), שמות הקבצים, השיחה של הבקשה, ושפת החלונית.

פלט (JSON, נבדק בשרת):
```
{ "message": "משפט או שניים בשפת החלונית",
  "files": [ { "name": "K-101.pdf", "dest": "CONSULTANTS/…/TASC-structural-plans-v04" } ],
  "steps": [ { "op": "move", "path": "", "from": ".../plans-v03", "to": ".../plans-@ver/plans-v03" },
             { "op": "mkdir", "path": ".../plans-v04", "from": "", "to": "" } ],
  "mode": "new-version" | "existing",
  "guide_add": "משפט להנחיה, או ריק" }
```
פעולות מותרות בלבד: `mkdir`, `move` (תיקייה), `move-contents` (הקבצים שבתוך תיקייה אחת עוברים לאחרת), וההעתקות.
**אין מחיקה.** "לרענן" תיקייה = `move-contents` ל-`@ver`. `""` = תיקיית הפרויקט עצמה. קובץ בלי יעד = לא מתויק.
כשאין אף יעד, ההודעה היא שאלה ו"אשר" לא מוצג. כש-Claude לא זמין — החלונית אומרת זאת, ואפשר לפתוח את
התיקייה (📂) ולתייק ידנית.

- כל נתיב בתכנית נבדק בשרת מול העץ, ושוב במחשב לפני ביצוע: אחרי נרמול, חייב להיות בתוך תיקיית הפרויקט.

- שינוי תיקיית הפרויקט, ההנחיה וצילום אנשי הקשר — רק למי שיש לו הרשאת כתיבה בפרויקט.

## ניסיונות שנפסלו (2026-10-22)

**פתיחת חלון מקישור בדפדפן.** התכנון המקורי: החלונית פותחת `projecthub-file:<token>` (פרוטוקול רשום ב-HKCU).

**חלון עץ תיקיות במחשב** (WinForms: עץ, רשימת קבצים, "גרסה חדשה / הוסף לקיימת", צעדים). נבנה ונבדק עם המשתמש:

3. **המשתמש מלווה את ההיררכיה.** Claude שואל שאלות ממוקדות על ארבעת האזורים המורכבים — **PUBLISH, Consultants,
   Receive, Permit** — והמשתמש עונה בכתיבה חופשית. מה שסוכם נשמר כהנחיית התיוק של הפרויקט (אותו טקסט שהתיוק
   משתמש בו), וממשיך להתעדכן מתיקונים ומ"תלמד: …".

ממומש על אותו מנגנון: משימות `pick`/`tree` לעוזר, שיחה עם Claude (מצב "מיפוי" במקום "תיוק"), והנחיה שנשמרת בשרת.

## מסלול מקומי: הקבצים לא עוברים דרך השרת (2026-10-22)

**למה.** בתכנית החינמית של Azure מותרים 165 MB ביום של נתונים יוצאים (BytesSent). כל קובץ שהעוזר מוריד מהשרת
נספר שם, וכמה מיילים כבדים היו עוצרים את כל האתר עד חצות UTC. Outlook הקלאסי מותקן ומחובר במחשבי המשרד, אז העוזר
שומר את הקבצים ממנו ישירות.

**הזרימה.**
1. **החלונית** פותחת את הבקשה (`POST /api/outlook/filing`) עם פרטי המייל שכבר יש לה (`internetMessageId`,
   `conversationId`, נושא, זמן קבלה, שולח) ועם `files: [{ name, size, outlookId }]` לכל קובץ מצורף רגיל — **בלי
   להעלות אותו**. השרת רושם `files[n] = { name, size, source: 'outlook' }` (n לפי הסדר). המייל עצמו (‎.eml) ומייל
   מצורף (attachmentType `item`) עדיין עולים כמו קודם (`source: 'upload'`), כי Outlook הקלאסי לא שומר ‎.eml.
2. **Claude** מקבל שמות וגדלים בלבד, כמו קודם.
3. **משימת `file`** מוסרת לעוזר גם את `mail: { internetMessageId, conversationId, subject, received, from }` ואת
   `source` של כל קובץ. `Run-Task.ps1` פונה ל-Outlook הקלאסי כמו סורק המייל (`Scan-Mail.ps1`): `New-Object -ComObject
   Outlook.Application` — מתחבר ל-Outlook שרץ, או מפעיל אותו ברקע אם אינו רץ (אותה התנהגות כמו בסורק). המייל נמצא לפי
   `PR_INTERNET_MESSAGE_ID` (שאילתת DASL ‏`0x1035001F`) בתיבת הדואר הנכנס, בפריטים שנשלחו ואז בשאר תיקיות הדואר של
   התיבה (עד 400; שם השיחה יכולה להיות אחרי העברה), ואם לא נמצא — לפי נושא + זמן קבלה ±2 דקות + שולח. הקבצים מותאמים
   לפי שם (בלי רישיות; בשמות כפולים — הגודל הקרוב ביותר, ואז הסדר) ונשמרים ב-`Attachment.SaveAsFile` לתיקייה הזמנית
   בשם `<n>`. קריאה בלבד: שום פריט לא מועבר, לא מסומן כנקרא ולא נשלח.
4. **גיבוי.** אם Outlook הקלאסי חסר, לא מחובר, או שהמייל/הקובץ לא נמצא — העוזר לא מתייק כלום ומחזיר
   `{ needUpload: [n…] }`. השרת רושם את הבקשה כממתינה להעלאה (`needUpload`, ומשחרר את `taskId`), החלונית (שעוקבת
   אחרי המשימה) מציגה "לא נמצא ב-Outlook במחשב — מעלה דרך השרת…", מעלה רק את הקבצים האלה
   (`POST /api/outlook/filing-file?id=&n=`), ומאשרת שוב; בפעם השנייה העוזר מוריד אותם מהשרת. בזמן התיוק עם קבצים
   מ-Outlook החלונית אומרת "שומר מ-Outlook במחשב…".
5. **תקציב יומי בשרת.** כל העלאה ל-`filing-file` נספרת כבתים שהשרת ישלח לעוזר (כל קובץ יורד פעם אחת), לפי יום UTC,
   ב-`filing.json` ‏(`budget: { day, bytes }`). העלאה שתעבור את `FILING_DAILY_BYTES` (ברירת מחדל 50 MB) נדחית לפני
   שהיא נשמרת — לפי `Content-Length` כבר לפני שהבתים מגיעים: ‏429 ‏`{ error: 'daily_budget' }`, והחלונית אומרת "גדול
   מדי למעבר דרך השרת היום — פתח את Outlook הקלאסי במחשב ונסה שוב". "אשר ותייק" מנסה שוב קודם את Outlook שבמחשב.

**בדיקות.** שרת: הבקשה בלי העלאה, `needUpload` ← העלאה ← אישור ← העוזר מוריד מהשרת, והתקציב (`FILING_DAILY_BYTES`
קטן בבדיקה, יום חדש מתחיל מאפס). מחשב (`FileHelper.Core.Tests.ps1`): אילו קבצים ומאיפה (`Get-NeededFiles`), התאמת
הקבצים (`Get-AttachmentMatch`), המסננים והתאמת המייל בגיבוי. חלק ה-COM ב-`Run-Task.ps1` דק, ונבדק בבדיקת קריאה-בלבד
מול Outlook הקלאסי במחשב של המשתמש (המייל האחרון עם קובץ מצורף נמצא לפי ה-message id ולפי נושא+זמן+שולח).
