# תיוק קבצים ממייל לתיקיית הפרויקט — מסמך עיצוב

**תאריך:** 2026-10-22
**קבצי יעד:** `outlook/taskpane.html` (כפתור "תייק בתיקיית הפרויקט"), מודול שרת חדש
`tools/local-server/filing.js` (+ חיבור ב-`outlook.js` / `server.js`), תיקייה חדשה `tools/file-helper/`
(חלון PowerShell במחשב + התקנה), `i18n-dict.js`.
**בסיס:** הענף של תוסף ה-Outlook (`claude/outlook-addin-99a83c`), `2026-10-21-outlook-addin-design.md`.
**סטטוס:** אושר בשיחה, ממתין לעיון במסמך הכתוב.

## הבעיה

מייל מיועץ מגיע עם תכניות; היום שומרים אותן ידנית לתיקיית הפרויקט בכונן הרשת, או דרך חלון
Receive של Folder Manager. התוסף כבר קורא את הקבצים המצורפים, אבל לא החלונית (דפדפן) ולא השרת
ב-Azure יכולים לכתוב לכונן הרשת של המשרד — התיוק חייב לקרות במחשב של המשתמש.

תבנית 154 התיקיות של Folder Manager לא מחזיקה בפועל: כל פרויקט קצת שונה (סוג פרויקט, טעויות).
לכן לא מסתמכים על התבנית אלא על **התיקייה הראשית של הפרויקט** ועל עץ התיקיות האמיתי שבה, ועל
הנחיית תיוק שהמשתמש כותב לכל פרויקט.

מחוץ להיקף: תיוק מתוך Project Hub עצמו (לא מהמייל), סנכרון עם `projects.json` של Folder Manager,
שינויים בריפו של Folder Manager.

## הזרימה

1. **בחלונית** (ליד הקבצים המצורפים, שם קיים "צרף קבצים"): כפתור **תייק בתיקיית הפרויקט**. בוחרים
   קבצים; הפרויקט הוא הפרויקט שנבחר בחלונית.
2. החלונית מעלה את הקבצים ל-`POST /api/outlook/filing` (מפתח `pho_` הרגיל), עם פרטי המייל
   (שולח, נושא, `conversationId`). השרת שומר אותם בתיקייה זמנית ומחזיר **אסימון** חד-פעמי.
3. אחרי ההעלאה החלונית מציגה כפתור-קישור **פתח את חלון התיוק** (`projecthub-file:<token>`): פתיחת תוכנה מקישור
   דורשת לחיצה טרייה, וההעלאה לוקחת יותר מהזמן שהדפדפן מרשה. הצורה המדויקת נקבעת בבדיקה המקדימה (ראו בסוף).
4. **בחלון במחשב** — האסימון הוא ההרשאה היחידה (אין מפתח שמור במחשב):
   1. `GET /api/filing/<token>` → שם הפרויקט, קוד, `folder`, `guide`, היסטוריה אחרונה, פרטי המייל, רשימת קבצים.
   2. **קישור ראשון** (אין `folder`): החלון מציע תיקייה תחת `@Omicron Projects` — לפי הקוד/שם מול
      `projects.json` של Folder Manager ושמות התיקיות — המשתמש מאשר או בוחר; אחר כך עורך את ההנחיה
      (טיוטה מוכנה). נשמרים ב-`PUT /api/filing/<token>/project`.
   3. החלון קורא את עץ התיקיות של הפרויקט (שמות תיקיות בלבד, עד עומק 5, עד 3,000 תיקיות) ושולח ל-
      `POST /api/filing/<token>/suggest`. Claude מחזיר **תכנית**: לכל קובץ תיקיית יעד, ורשימת צעדים.
   4. החלון מציג מי שלח לתיוק (האסימון מספיק כדי לפתוח אותו), את העץ עם היעד מסומן, ואת הצעדים בשפה פשוטה. המשתמש יכול לבחור תיקייה אחרת בעץ,
      להחליף "גרסה חדשה" ⇄ "הוסף לקיימת", ולאשר.
   5. החלון מוריד את הקבצים (`GET /api/filing/<token>/file/<n>`), מבצע את הצעדים, ומדווח
      `POST /api/filing/<token>/done` עם מה שבוצע בפועל. האסימון נסגר והקבצים הזמניים נמחקים.
5. **בשרת** אחרי `done`: רשומה בהיסטוריית התיוק של הפרויקט; אם השרשור מקושר למשימה — רשומה ביומן
   המשימה ("תויק: plan.pdf ← CONSULTANTS\…\plans-v04") דרך המנגנון של הרישום האוטומטי.

## מה נשמר איפה

- **שרת, `data/filing.json`** (מסמך חדש, שרת בלבד, לא דרך `/api/<app>`):
  `{ projects: { <hubProjectId>: { folder, guide, updatedBy, updatedAt, log: [ … עד 200 ] } } }`.
  רשומת log: `{ at, by, from (שולח), subject, file, dest (יחסי לתיקיית הפרויקט), action }`.
- **שרת, תיקייה זמנית** `DATA_DIR/filing-tmp/<token>/` — נמחקת ב-`done`, בביטול, או כשפג תוקף.
- **מחשב**, `%LOCALAPPDATA%\ProjectHub\file-helper.json`: `{ projectsRoot }`. מזוהה אוטומטית כתיקיית האב
  הנפוצה של הנתיבים ב-`%LOCALAPPDATA%\FolderManager\projects.json`; אחרת בוחרים בתיבת בחירת תיקייה.

## התכנית של Claude

קלט: ההנחיה, עץ התיקיות (נתיבים יחסיים), 30 התיוקים האחרונים בפרויקט, שולח ונושא, שמות הקבצים.

פלט (JSON, נבדק בשרת):
```
{ "files": [ { "name": "A-101.pdf", "dest": "CONSULTANTS/TASC-structural/TASC-structural-plans/TASC-structural-plans-v04" } ],
  "steps": [ { "op": "move", "from": ".../plans-v03", "to": ".../plans-@ver/plans-v03" },
             { "op": "mkdir", "path": ".../plans-v04" } ],
  "mode": "new-version" | "existing",
  "why": "משפט אחד" }
```
פעולות מותרות בלבד: `mkdir`, `move` (תיקייה), `move-contents` (הקבצים שבתוך תיקייה אחת עוברים לאחרת), וההעתקות
מ-`files`. **אין מחיקה.** כשההנחיה אומרת "לרענן" תיקייה (למשל updated-PDF), הקבצים הישנים מועברים
(`move-contents`) ל-`@ver` הסמוך. כל קובץ בתכנית נושא `n` (המיקום שלו בבקשה), כך ששני קבצים באותו שם לא מתבלבלים.
כש-Claude לא זמין או מחזיר תכנית לא תקינה — החלון נפתח בלי הצעה, והמשתמש בוחר תיקייה בעץ.
"גרסה חדשה" ⇄ "הוסף לקיימת" בחלון, בלי לפנות שוב ל-Claude: חזרה למצב ש-Claude הציע מחזירה את התכנית שלו
כמו שהייתה; המצב השני מחושב מהתיקיות (קיימת ← ה-`vNN` הגבוה ביותר; חדשה ← ה-`vNN` הבא + `mkdir`), ומהתכנית
של Claude נשארים רק צעדי `move-contents`. בחירת תיקייה בעץ קובעת אותה לקבצים המסומנים, מבטלת את הצעדים,
ונהיית הבסיס למעבר בין המצבים.

## בטיחות

- כל נתיב בתכנית נבדק במחשב לפני ביצוע: אחרי נרמול, חייב להיות בתוך תיקיית הפרויקט (לא `..`, לא נתיב מוחלט).
  צעד לא תקין עוצר את כל התכנית לפני שמשהו מתבצע.
- קובץ יעד בשם קיים: מקבל ` (2)`, ` (3)`…; אף פעם לא דורסים.
- האסימון: 32 בתים אקראיים, תוקף 15 דקות, חד-פעמי (`done` סוגר), קשור לאדם שיצר אותו ולפרויקט; השרת
  שומר רק hash. העלאה: עד 20 קבצים, עד 20MB כל אחד (מגבלת השרת, כמו `/api/outlook/upload`).
- `PUT …/project` משנה רק את `folder` ו-`guide` של הפרויקט שבאסימון, ורק אם ליוצר האסימון יש הרשאת כתיבה בפרויקט.

## התקנה

`tools/file-helper/Install-FileHelper.ps1` (בלי הרשאות מנהל): מעתיק את `File-Helper.ps1` ל-
`%LOCALAPPDATA%\ProjectHub\`, רושם `HKCU:\Software\Classes\projecthub-file` (פותח PowerShell מוסתר עם
החלון), ומזהה את `projectsRoot`. `Uninstall-FileHelper.ps1` מסיר. README בעברית כמו של סורק המייל.
כתובת השרת נשמרת בהתקנה (ברירת מחדל `https://kkarc-hub.azurewebsites.net`).

## שפה

כל טקסט בחלונית — עברית במקור + טבלת `HE_EN` שבתוך `outlook/taskpane.html` (החלונית לא טוענת את `i18n.js`). בחלון במחשב — טבלת `HE`/`EN` בסקריפט; השפה נקבעת
לפי `lang` שמגיע בתשובת `GET /api/filing/<token>` (השפה שהחלונית רצה בה), והחלון מתהפך RTL/LTR.

## סיכון לבדוק ראשון

פתיחת `projecthub-file:` מתוך ה-iframe של התוסף. ב-Outlook בכרום צפוי לעבוד עם אישור של הדפדפן; ב-Outlook
החדש/הקלאסי (WebView2) ייתכן שייחסם — אז הקישור לחיצה/העתקה הוא הדרך. נבדק לפני שאר העבודה.
