# תוסף Outlook ל-Project Hub — מסמך עיצוב

**תאריך:** 2026-10-21
**קבצי יעד:** תיקייה חדשה `outlook/` (קובץ הגדרה + חלונית), מודול שרת חדש
`tools/local-server/outlook.js`, `server.js`, `mcp.js` (חשיפת פונקציות קיימות), `mail.js` /
`mail-store.js` / `tools/mail-scan/` (מתג ההצעות ורישום אוטומטי), `project_hub_01.html` +
`i18n-dict.js` (הגדרות).
**סטטוס:** אושר בשיחה, ממתין לעיון במסמך הכתוב.

## הבעיה

סריקת המייל הקיימת (`2026-10-20-mail-task-suggestions-design.md`) יוצרת עבודה כפולה: קוראים את
המייל, ואחר כך קוראים את הצעות ה-AI, שלעתים קרובות חלשות. הכיוון הפוך — "משיכה": פועלים מתוך
המייל שכבר פתוח, בצעד אחד, באותה תחושה של הצ'אט עם Claude והקונקטור (כותבים בחופשיות → משימה
נוצרת או מתעדכנת). מוח אחד — כלי הקונקטור והכללים של סקיל ה-hub — מאחורי נקודת כניסה דקה.

מחוץ להיקף: בוט טלגרם (נפרד), WhatsApp, טלפון.

## ארכיטקטורה

```
Outlook (כרום / חדש / קלאסי)
  └─ outlook/taskpane.html  (Office.js; קוראת את המייל הפתוח)
       │  Authorization: Bearer <מפתח אישי>   (שלב 2: אסימון Office SSO)
       ▼
  שרת ה-Hub — tools/local-server/outlook.js
   ├─ GET  /api/outlook/me          מי אני, תפקיד
   ├─ GET  /api/outlook/projects    הפרויקטים שלי (כמו list_projects)
   ├─ POST /api/outlook/context     המייל → פרויקט משוער + משימה קשורה + רישום אוטומטי
   ├─ POST /api/outlook/parse       טקסט חופשי + המייל → Claude → הצעה מובנית
   ├─ POST /api/outlook/apply       הצעה מאושרת → create_tasks / update_task / צירוף
   ├─ POST /api/outlook/undo        ביטול משימה שנוצרה מהתוסף (10 דקות)
   └─ POST /api/outlook/upload      המייל (.eml) או קובץ מצורף → קובץ במשימה
                 │
                 ├─ mcp.runToolAs(...)   ← אותם כלים, הרשאות והתאמות שמות כמו הקונקטור
                 └─ data/outlook_links.json   שרשור ↔ משימה, משותף למשרד
```

### 1. התוסף — `outlook/`

- `manifest.xml` — `VersionOverrides` 1.1, `MailHost`, כפתור בסרגל של מייל בקריאה
  (`MessageReadCommandSurface`) שפותח חלונית, `SupportsPinning` (החלונית נשארת פתוחה במעבר בין
  מיילים). דרישה מינימלית: `Mailbox` 1.8 (קבצים מצורפים); `getAsFileAsync` (שמירת המייל כ-.eml)
  מ-1.14 — כשאינו נתמך, כפתור "צרף את המייל" מוסתר. מזהה קבוע (GUID), שם "Project Hub", אייקונים
  מהקיימים. קובץ אחד עם `{{BASE}}`: השרת ממלא בו את הכתובת שלו כשהוא מגיש את
  `/outlook/manifest.xml`, כך שהקובץ שהורד מהשרת המקומי (`https://localhost:3443`) מצביע עליו, וזה
  שהורד מ-Azure מצביע על Azure. כתובת החלונית היא `/outlook/taskpane` (בלי `.html`): השרת מפנה
  `.html` לכתובת בלי הסיומת ומאבד בדרך את הפרמטרים ש-Outlook מוסיף.
- `taskpane.html` — קובץ אחד, בלי בנייה, כמו שאר האתר; JavaScript רגיל (לא React — החלונית
  קטנה). Office.js נטען מ-`appsforoffice.microsoft.com` (חובה לפי מיקרוסופט; לא ניתן לאירוח עצמי).
- **מה נקרא מהמייל:** `conversationId`, `internetMessageId`, `itemId`, נושא, שולח (שם וכתובת),
  To/Cc, תאריך, גוף כטקסט (`body.getAsync('text')`, 6,000 תווים ראשונים), רשימת קבצים מצורפים
  (שם, גודל, סוג, `isInline`). `Office.context.mailbox.addHandlerAsync(ItemChanged)` מרענן כשעוברים
  מייל בחלונית נעוצה.
- **מפתח:** נשמר ב-`Office.context.roamingSettings` (עובר בין מחשבים ו-Outlook-ים של אותו חשבון).
  מסך כניסה: "הדבק מפתח" + הסבר איפה מפיקים אותו (הגדרות → גישה מהירה → תוסף Outlook).
- **שפה:** עברית במקור, אנגלית ממילון קטן בתוך הקובץ (כמו `HE_EN` ב-`login.html`). כפתור English /
  עברית בראש החלונית, והבחירה נשמרת ב-`roamingSettings`. (ההעדפה של ה-Hub נשמרת ב-`localStorage`, שהחלונית
  בתוך Outlook לא רואה.) `dir` מתהפך, CSS לוגי בלבד. תוכן מהמייל ומהמשימות מוצג כפי שהוא.
- **מצב הדגמה:** `/outlook/taskpane?demo` מחוץ ל-Outlook מציג מייל לדוגמה, לבדיקה בדפדפן.

### 2. החלונית — מה רואים

1. **פרויקט** — בראש, משוער לפי הסדר: (א) השרשור קשור → הפרויקט של המשימה; (ב) כתובת השולח
   הופיעה בשרשור קשור → אותו פרויקט (הנפוץ מביניהם); (ג) קוד או שם פרויקט מופיע בנושא (התאמה
   סלחנית לעברית, `norm` מ-`mcp.js`); (ד) ריק. ניתן להחלפה מרשימה.
2. **כרטיס משימה קשורה** (כשיש): כותרת, שלב, סטטוס, אחראים, תאריך יעד, שלושת העדכונים
   האחרונים, קישור "פתח ב-Hub". אם המייל הנוכחי עוד לא נרשם — נרשם עכשיו (ראו "רישום אוטומטי"),
   ובכרטיס: **הפוך לעדכון מלא** (סטטוס עדכון + תחום שמחזיק בכדור + טקסט) / **הסר**.
3. **תיבת "מה לעשות עם המייל הזה?"** — טקסט חופשי, Enter שולח (Shift+Enter שורה חדשה).
4. **התוצאה** מתחת לתיבה:
   - **משימה חדשה** — נכתבת מיד: "נוצרה: [כותרת] · [שלב] · [אחראי] · [תאריך]" + **בטל** + קישור.
     השרשור נקשר למשימה.
   - **עדכון** — כרטיס הצעה: המשימה, טקסט העדכון, סטטוס עדכון, תחום שמחזיק בכדור, (שינויי שדות אם
     ביקשת: תאריך יעד, אחראים, סטטוס משימה). כל שדה ניתן לעריכה. **אשר** / **בטל**. אחרי אישור —
     השרשור נקשר למשימה (אם לא היה).
   - **צירוף** — המייל עצמו (.eml) ו/או קבצים מצורפים מסומנים, למשימה שנבחרה. **אשר** / **בטל**.
   - **שאלה** — כש-Claude לא בטוח: שאלה אחת עם 2–4 אפשרויות ללחיצה, ותשובה חופשית.
5. **מסלול ידני** — שלושה כפתורים קטנים: משימה חדשה / עדכון / צירוף. כל אחד פותח טופס קצר
   (בחירת משימה בחיפוש, דרך `search_tasks`). עובד גם כש-Claude לא זמין.

### 3. השרת — `tools/local-server/outlook.js`

מחובר ל-`server.js` כמו `mail.js`: `handlePublic` לפני שער ה-Easy Auth (אימות ב-Bearer).

- **מפתח אישי:** `mail-tokens.js` הקיים, על קובץ נפרד `data/outlook_tokens.json`, תחילית `pho_`.
  מפתח אחד לאדם; הפקה ב-`/api/outlook-connection` (מחובר, Easy Auth) — `GET` מצב, `POST` הפקה
  (מוצג פעם אחת), `DELETE` ביטול. מפתח נפרד ממפתח הסורק, כדי שביטול של אחד לא ישבור את השני.
- **CORS:** החלונית מוגשת מאותו מקור כמו ה-API, כך שאין צורך ב-CORS. `OPTIONS` לא נדרש.
- **החלונית והקבצים הסטטיים** (`/outlook/<שם>` עם `.html` / `.xml` / `.png` או בלי סיומת) מוגשים
  **לפני הכניסה** (אין בהם נתונים), וגם במצב ענן.
- **`/api/outlook/projects`** — `mcp.runToolAs(..., 'list_projects')`.
- **`/api/outlook/context`** — גוף: נתוני המייל (בלי הגוף המלא). מחזיר `{ projectId, why, linked:
  { projectId, taskId, task: {…כרטיס…}, logged: bool } | null }`. רושם את המייל כעדכון אוטומטי
  כשהשרשור קשור והמייל עוד לא נרשם.
- **`/api/outlook/parse`** — גוף: `{ text, mail, projectId, linkedTaskId? }`. קריאה אחת ל-Claude:
  - הקשר: המייל (עטוף כתוכן לא-אמין, כמו ב-`mail-ai.js`), הטקסט של המשתמש (ההוראה), תאריך היום,
    ומהפרויקט הנבחר: השלבים, התחומים, העדיפויות, הצוות, סטטוסי העדכון והמשימות הפתוחות (מזהה,
    כותרת, שלב) — אותה שליפה כמו `get_project`; המשימה הקשורה מסומנת.
  - ההנחיה בנויה מהכללים של `INSTRUCTIONS` ב-`mcp.js` ושל סקיל ה-hub (שלב ברירת מחדל, עדכון
    ולא שינוי כותרת, בעל העדכון הוא תחום, תאריכים).
  - פלט מובנה (JSON Schema): `{ action: 'create'|'update'|'attach'|'ask', task: {title, stage,
    discipline, priority, assignees[], start_date, due_date, note}, target: {taskId}, update: {text,
    update_status, owner}, changes: {due_date, status, assignees[]}, attach: {mail: bool,
    attachments: [name]}, question: {text, options[]}, summary }`.
  - **ניקוי:** כל שם (שלב, תחום, אדם, משימה, סטטוס) נבדק מול הפרויקט — ערך לא קיים נמחק, ואם
    הוא חיוני (משימת יעד לעדכון) ההצעה הופכת ל-`ask`.
  - `action: 'create'` נכתב מיד בשרת (`create_tasks`, עם `mail_url` כשיש קישור, והשולח, הנושא
    והתאריך בהערה), השרשור נקשר, והתשובה מחזירה את המשימה שנוצרה + `undoToken`. השאר מוחזרים
    כהצעה בלבד.
  - **מודל:** `OUTLOOK_AI_MODEL`, ברירת מחדל `claude-sonnet-5-5` (מהירות בחלונית). אותו
    `ANTHROPIC_API_KEY` ואותו לקוח כמו `mail-ai.js` (`makeClient` משותף).
- **`/api/outlook/apply`** — הצעה מאושרת (אחרי עריכה) → `update_task` (עם `add_update`,
  `add_mail_url`) או צירוף. השרשור נקשר.
- **`/api/outlook/undo`** — `{ undoToken }` → `delete_task` על המשימה שנוצרה, רק אם נוצרה מהתוסף
  ע״י אותו אדם, בתוך 10 דקות, ועוד לא נוספו לה עדכונים מאז. אחרת 409 עם הסבר. הקישור נמחק.
- **`/api/outlook/upload`** — `POST` גולמי (`?name=&taskId=&project=`), עד 25MB; נשמר ב-
  `saveAttachment` הקיים ומצורף למשימה כמו ב-`attach_file` (אותו `attachInto` — ייחשף מ-`mcp.js`).
- **שגיאות:** מפתח חסר/שגוי → 401; תפקיד צפייה → 403 עם הודעה (`ToolError` של `canWrite`);
  `ToolError` אחר → 400 עם ההודעה; Claude נכשל / אין מפתח → 503 `{ error: 'ai_unavailable' }`, והחלונית
  מציעה את המסלול הידני. השרת לא יוצא בגלל זה; `/health` מוסיף `outlookAi`.

### 4. קישור שרשורים — `data/outlook_links.json`

```
{ threads: { <threadKey>: { projectId, taskId, linkedBy, linkedAt,
                            messages: [{ internetMessageId, received, from, subject, eventId|null }] } },
  undo:    { <sha(undoToken)>: { who, projectId, taskId, exp } } }
```

- **מפתח השרשור (`threadKey`)** — נבדק 2026-10-22: ה-`conversationId` של Office.js (Outlook בדפדפן) הוא
  base64 של כותרת + **מזהה תיבת הדואר** (GUID כטקסט, שונה מאדם לאדם) + `0x10 0x00` + **16 בתים של מזהה
  השיחה**. 16 הבתים האלה, כ-hex באותיות גדולות, הם בדיוק ה-`ConversationID` של Outlook הקלאסי (COM) — אותו
  ערך נמצא בשלושת המיילים של השרשור בתיבה. לכן `threadKey` = 32 תווי hex של מזהה השיחה: בתוסף מחלצים
  אותם מה-`conversationId` (base64 רגיל או url-safe; אם המבנה לא מזוהה — המחרוזת כמו שהיא), ובסורק לוקחים
  את `ConversationID` כמו שהוא. כך אותו שרשור מתאים בין תיבות של אנשים שונים ובין התוסף לסורק.
  כגיבוי: מייל ששדות `In-Reply-To` / `References` שלו מכילים `internetMessageId` שכבר רשום בשרשור — שייך לשרשור.
- גם המשימה נושאת את הקישור: `mails: [{ url, added, threadKey, subject }]` (השדה הקיים; `url` הוא
  קישור לפתיחת המייל ב-Outlook בדפדפן כשיש, אחרת ריק ו-`MailLink` מציג נושא בלבד — שינוי קטן בדף).
- מייל שנרשם בשרשור נשמר ב-`messages` עם מזהה העדכון שנוצר, כך שאינו נרשם פעמיים (לא ע״י התוסף ולא
  ע״י הסורק), ו"הסר" / "הפוך לעדכון מלא" יודעים איזה עדכון לשנות.
- משימה שנמחקה → הקישור שלה נמחק בפעם הבאה שנתקלים בו.
- הקובץ משותף לכל המשרד (שרשור עם כמה נמענים נקשר פעם אחת). קורא רק השרת.

### 5. רישום אוטומטי ומתג ההצעות

- **רישום אוטומטי:** עדכון במשימה עם `status: 'update'` (לא משנה את הסטטוס הנגזר — לבדוק מול
  `getMostRecentEventStatus` בדף), `assignee` = הבעלים הנוכחי (ללא שינוי), `title` = "מייל מ-[שולח]:
  [נושא]", `mail: {threadKey, internetMessageId, subject}`, `auto: true`. רשומת היסטוריה "נרשם
  אוטומטית מהמייל".
- **מי רושם:** (א) התוסף, כשנפתח מייל משרשור קשור (`/api/outlook/context`); (ב) הסורק, בכל ריצה:
  השרת בודק כל מייל נקלט מול `outlook_links.json` **לפני** הטריאז' — מייל משרשור קשור נרשם כעדכון
  ואינו נשלח ל-Claude. הסורק צריך לשלוח בנוסף `conversationId` (COM) ו-`inReplyTo` / `references`
  (מכותרות ההודעה).
- **"הפוך לעדכון מלא":** פותח את טופס העדכון עם הטקסט הקיים; אישור מחליף את העדכון האוטומטי (אותו
  מזהה, `auto` נמחק). **"הסר":** מוחק את העדכון האוטומטי (המייל נשאר מסומן כנרשם, כדי שלא יחזור).
- **מתג ההצעות:** במסמך המייל האישי `suggest: false` (ברירת מחדל). כבוי → מיילים שאינם משרשור קשור
  מסומנים `seen` ולא נשלחים ל-Claude; הפאנל "הצעות מהמייל" והחלונית הקופצת לא מוצגים. הגדרות →

## שלב 2: כניסה אוטומטית והתקנה מרכזית (עם המנהל)

- **Entra, אפליקציית `kkarc-hub`:** Expose an API — `api://kkarc-hub.azurewebsites.net/<client-id>`,
  scope `access_as_user`; Authorized client applications: לקוחות Office (`ea5a67f6-b6f3-4338-b240-
  c655ddc3cc8e` — כל לקוחות Office); הרשאות Delegated: `openid`, `profile`, `email`; Grant admin consent.
- **קובץ ההגדרה:** `WebApplicationInfo` עם ה-Client ID וה-URI.
- **החלונית:** `Office.auth.getAccessToken()` → Bearer; בכישלון — חוזרת למפתח האישי.
- **השרת:** מאמת את האסימון (חתימת Entra מ-JWKS, `aud`, `iss` של הדייר, תוקף) ולוקח את
  `preferred_username`. בלי ספרייה חדשה אם אפשר (`crypto.verify` עם JWK).
- **התקנה מרכזית:** Microsoft 365 admin center ← Settings ← Integrated apps ← Upload custom apps ←
  קובץ ההגדרה (כתובת ה-Azure), לכל המשרד.
- **נוסח לבקשה מהמנהל** (לשלוח כשמגיעים לשלב 2):

  > המשתמש אוטומטית. מה שנדרש: (1) ב-Entra, באפליקציה kkarc-hub (Client ID
  > `86a60dbe-9c87-46e3-a486-8131f1238961`): Expose an API עם scope `access_as_user`, הוספת לקוחות Office
  > כ-Authorized client, ו-Grant admin consent ל-`openid`, `profile`, `email`. (2) ב-Microsoft 365 admin
  > center ← Integrated apps: Upload custom app עם הקובץ המצורף, לכל המשתמשים.
